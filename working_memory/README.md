# Repeat detection task: browser version, hosted from your laptop

`task.html` is a browser port of `vwm_repeat_detection_task.py`. `server.py` serves it from your laptop and writes each session's data into `data/<subject>/`, using the same file names and columns as the PsychoPy version. Collaborators open a link; the task runs in their own browser, so stimulus timing and key timestamps are measured on their machine. They install nothing.

Put this `web/` folder inside `working_memory/`.

## One-time setup

Install `cloudflared` (it makes the public link):

- macOS: `brew install cloudflared`
- Windows: `winget install --id Cloudflare.cloudflared`

The server itself uses only the Python standard library (3.8+), so the Python that came with PsychoPy works.

## Each session

From the `working_memory` folder:

```bash
caffeinate -i python3 web/server.py --tunnel     # macOS: caffeinate keeps the laptop awake
```

After a few seconds it prints a link like

```
https://some-random-words.trycloudflare.com/?key=Xy3k...
```

Send that whole link, including the `?key=` part. The key is what allows data to be saved; without it the page still runs but can't send data. You can add `&subject=12` to pre-fill a subject number.

Keep the terminal window open, and the laptop awake and online, until everyone has finished. Each saved file is reported in the terminal as it arrives. Press Ctrl+C to stop.

Notes:

- The link changes every time you restart the server (Cloudflare quick tunnels are temporary). For a permanent link, set up a named Cloudflare tunnel on your own domain, or an ngrok static domain, pointing at `http://localhost:8000`.
- Use `--key yourkey` to keep the same key between restarts, `--port` to change the port, and `--data-dir` to write somewhere other than `./data`.
- If your laptop goes offline mid-session, the participant's page retries; if saving still fails, the end screen offers the files for download so they can email them to you.

## What participants see

A setup page asks for subject number, practice on/off and viewing distance, then has them size an outline to match a bank card held against the screen. That calibration sets the pixels-per-cm, so stimuli come out the same visual angle on any monitor. The task then runs full screen with the same instructions, practice (repeated once if hit rate < 0.5), feedback and 15-minute test as the PsychoPy version.

## Data

Same files as PsychoPy, in `data/<subject>/`:

- `VWMcentre_s<N>_events.csv`, `VWMcentre_s<N>_blocks.csv` (appended across runs)
- `VWMcentre_s<N>_<run_id>_<phase>_sequence.csv`
- `VWMcentre_s<N>_<run_id>_params.json`

The params file records `"platform": "browser"`, the browser's user agent, the screen calibration (`px_per_cm_css`, derived `width_cm`) and the symbol size in pixels, so browser and lab runs can be told apart by `run_id`.

## Differences from the PsychoPy version

- **Sizes in degrees.** `symbol_height_deg` = 3.456 reproduces the lab laptop's 200 px symbol (3024 px across 52 cm at 57 cm, from its params files). If your laptop's real screen width isn't 52 cm, adjust this value.
- **Sequences.** Generated by a seeded JavaScript RNG with the same rules and seeds, so subject N's sequence is reproducible but not identical to PsychoPy's. Every sequence is still saved.
- **Leaving full screen ends the task** (the browser's Escape key exits full screen), logged as `Stream Aborted` with partial data saved, like Escape in PsychoPy.
- **Extra event types:** `Focus Lost` / `Focus Regained` when another window or tab takes focus mid-stream.
- **Key timing** uses the browser's keydown timestamps (typically within a few ms; less precise than psychtoolbox). Refresh rate is measured at the start, and symbol and ISI durations are snapped to whole frames, as in PsychoPy.
